# Contributing to ReturnIt

Welcome to ReturnIt! Contributions that improve security, reliability, and usability are welcome.

## How to Report a Vulnerability

1. Inspect the project and identify a potential vulnerability.
2. Check whether the issue has already been reported.
3. Report security vulnerabilities privately using GitHub's private vulnerability reporting feature, if available.
4. Include the affected component, reproduction steps, potential impact, and suggested remediation.

Do not publish credentials, personal information, or sensitive exploit details in public issues.

## How to Submit a Fix

1. Fork the repository.
2. Create a branch for your fix.
3. Make your changes.
4. Test the changes.
5. Submit a pull request describing the problem and solution.

## Supabase Security Changes

Contributors may submit proposed SQL migrations and changes to Supabase security policies through pull requests.

Contributors must not commit passwords, service-role keys, database credentials, or other secrets.

Changes to the live Supabase project require an authorized deployment process and appropriate review.

## Testing Rules

Use authorized testing methods and dummy accounts. Do not access, modify, or delete other users' private data.
